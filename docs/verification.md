# Проверка Telegram Serverless

Источники проверены 10 октября 2026: корневой AGENTS.md, docs/tgcloud-sdk.md,
https://core.telegram.org/bots/serverless и официальный telegram-web-app.js.
Проект создан через npm create @tgcloud/bot SyToDoBot; установлен CLI 0.2.0.

| Требование | Реализация |
| --- | --- |
| V8 runtime, только официальный SDK | Импорты `sdk`, `sdk/db` и относительные `.js` внутри tgcloud |
| Endpoint contract | `export default async function(input, ctx)` |
| Проверенная авторизация | Только `ctx.initData.user.id`; платформа отклоняет неверный initData до выполнения |
| Вызов из React | Callback-контракт `Telegram.WebApp.Serverless.call` |
| Ошибки | `EndpointError` с машинным кодом; generic error для неожиданных исключений |
| SQLite | `table`, `integer`, `text`, `boolean`, `index`, `check`, `sql` из sdk/db |
| Асинхронные запросы | `await .all()`, `.get()`, `.run()`, `db.$count()` |
| RETURNING | Используется документированный массив строк для table-bound returning().run() |
| Изоляция | Owner predicate для SELECT/UPDATE/DELETE/count; INSERT устанавливает owner |
| Размещение frontend | `static.source: dist`, SPA, immutable только для хешированных assets |
| Совместимость Telegram Web | Нет X-Frame-Options или запрещающего frame-ancestors |
| Темы и смартфоны | themeChanged, safe area, адаптивный CSS, reduced motion, BackButton |
| Секреты | Только штатное состояние CLI, исключённое из Git; нет секрета в frontend |
| Миграции | После разрешения пользователя выполнен `tgcloud migrate --local --safe`: создана новая tasks без изменения существующих данных |
| Команды в чате | handlers/message; владелец из Telegram message.from.id, только личный чат |
| Inline-кнопки | handlers/callback_query; владелец из callback_query.from.id, никогда из callback_data |
| Меню | Официальные setMyCommands с chat scope и setChatMenuButton с MenuButtonWebApp |

Автоматические проверки логики запускаются с настоящей локальной SQLite и
тестовым адаптером документированного подмножества SDK. Они проверяют сохранность
после закрытия/открытия базы, CRUD, IDOR, подмену userId, изоляцию счётчиков,
идемпотентность, валидацию, SQL-параметры, фильтры и пагинацию.
Адаптер находится только в tests/ и не включается в deployment.

Расширение чат-бота сверено с официальной Bot API документацией:
https://core.telegram.org/bots/api. Проверено 12 backend-тестов: 6 исходных
и 6 для команд/кнопок. Чат-тесты покрывают все зарегистрированные команды,
регистрацию меню, общий CRUD с Mini App, повторную доставку /add, пагинацию,
поддельные task ID, несовпадение chat ID и отправителя, HTML-экранирование,
подтверждение и отмену удаления, устаревшие кнопки и сбой настройки меню.
Bot API вызовы в этих тестах перехватываются; реальные сообщения при разработке
не отправляются. После разрешения пользователя deploy и безопасная миграция
выполнены; чат использует опубликованные обработчики.

Официальный runtime дополнительно проверен командой `tgcloud run` для getProfile
с тестовым контекстом. Модули и объявления схемы успешно загрузились, профиль
вернулся в документированном формате. Это не проверка подлинности initData:
CLI run намеренно принимает непроверенный контекст разработчика.

Браузерные проверки используют официальный WebApp SDK, локальную SQLite и
тестовый перехват транспорта. Они покрывают мобильный CRUD, светлую/тёмную тему,
повторное открытие, ошибку refresh после успешной мутации, отмену удаления,
отсутствие горизонтального скролла и экран вне Telegram на нескольких ширинах.

## Календарь, прокручиваемое время и самостоятельные напоминания

11 октября 2026 добавлены собственный календарь с выбором месяца/года,
кнопками сегодня/завтра и двумя вертикальными scroll-snap колонками времени.
Отдельный раздел напоминаний поддерживает создание, изменение, удаление,
историю отправки и повтор через 10 минут; тот же бот получил /remind,
/reminders и inline-кнопки управления. Переход по ссылке редактирования
проверяет владельца на сервере. Backend использует только официальный SDK.

Схема SQLite не менялась: для самостоятельных напоминаний сервер добавляет
префикс reminder: к приватному request_key. Алфавит клиентского requestId
исключает двоеточие. Все CRUD, списки и счётчики ограничены владельцем и
namespace; endpoint задач не может изменить даже своё отдельное напоминание.
Миграция --dry-run подтвердила отсутствие изменений схемы.

npm run check прошёл: 25 backend-тестов на настоящей SQLite, проверка runtime,
TypeScript и Vite build. Все 6 браузерных сценариев прошли с официальным
WebApp SDK и тестовым перехватом транспорта. В светлой и тёмной темах на
320 px проверены календарь, настоящая прокрутка колонки минут колесом,
клавиатура, создание/повторное открытие/изменение/история/повтор/удаление,
отсутствие горизонтального скролла. Изображения интерфейса проверены визуально.

Новые backend-тесты проверяют межпользовательскую и межтиповую изоляцию,
неподделываемый namespace, идемпотентное создание, параллельную отправку,
экранирование названия и описания, сохранение состояния при переименовании,
повторные callback и удаление. Реальный Telegram runtime listReminders через
CLI успешно загрузил новые модули и выполнил SDK LIKE/NOT LIKE запросы.
Этот CLI-контекст разработчика не является проверкой подлинности initData.

## Подготовленное обновление: циклы и уведомление заранее

11 октября 2026 реализованы ежедневные повторения, через день и по выбранным
дням недели. Самостоятельным напоминаниям и задачам доступны 5/10/15 минут
и целый пользовательский интервал 0–10080 минут. Дата/время относятся к событию.
Повторение хранит нормализованный сервером IANA timezone, исходную дату и
минуту дня. Клиентские anchorDate/minuteOfDay игнорируются.

npm run check прошёл: 24 backend-модуля, 34 теста на SQLite, TypeScript и
Vite production build. Все 8 браузерных сценариев прошли, включая обе темы
на 320 px, сохранение своего интервала у задачи, все три режима повторения,
выбор дней, переоткрытие, историю, повтор через 10 минут и удаление цикла.
Настройки и списки проверены по screenshots. Исправлено повторное открытие
пустой формы после сохранения по ссылке из бота: action/edit убираются из URL.
Проверка исходников на credential values и git diff --check прошли.

Новые тесты покрывают повторения при параллельных worker, долгие задержки без
потока пропущенных отправок, сохранение исходной даты при переименовании,
изменение интервала и отключение повторений. Проверены DST в Европе/Киеве и
Париже (разрыв сдвигается вперёд, повторяющийся час отправляется один раз),
смещение Непала +05:45, границы недели, неверные timezone и пустые дни.
Списки и счётчики изолированы по владельцу/типу. История содержит последнюю
доставку каждой серии; активная серия также остаётся в ожидающих.

Повтор цикла через 10 минут создаёт идемпотентную разовую копию, не сдвигая
цикл. Приватный namespace копии содержит двоеточия, недоступные requestId
клиента. INSERT ... SELECT через sdk.db.run(sql) атомарно проверяет владельца
и существование исходной серии, чтобы конкурентное удаление не оставляло
отдельную отправку. Удаление серии удаляет её ожидающие копии. Старый callback
проверяет timestamp последнего события.

В настоящем Telegram runtime выполнены временные readonly probes через CLI:
Intl.DateTimeFormat с Europe/Kyiv доступен; новый модуль recurrence правильно
вычислил 09:00 по местным часам 25 октября после перехода на зимнее время
(UTC+02), с уведомлением за 10 минут. Эти probe endpoints удалены из проекта
и не опубликованы. Новая схема с официальным sdk/db json() загрузилась.

tgcloud migrate --local --dry-run показал только две безопасные операции:
ALTER TABLE tasks ADD COLUMN recurrence TEXT;
ALTER TABLE tasks ADD COLUMN last_reminder_due_at INTEGER;
Тест миграции на настоящей SQLite подтвердил побайтовое сохранение прежних
полей уже запланированной задачи и отправленного разового напоминания.
На момент подготовки миграция не применена, новая версия не опубликована
и не отправлена в GitHub: main используется работающим production-scheduler,
поэтому обновление его кода выполняется только после добавления полей.
В соответствии с первоначальным требованием пользователя запрошено
разрешение на эти две операции и публикацию; cloud revision остаётся 5.
