# Проверка Telegram Serverless

Источники проверены 10 октября 2026: корневой AGENTS.md, docs/tgcloud-sdk.md,
https://core.telegram.org/bots/serverless и официальный telegram-web-app.js.
Проект создан через npm create @tgcloud/bot SyToDoBot; установлен CLI 0.2.0.

| Требование | Реализация |
| --- | --- |
| V8 runtime, только официальный SDK | Импорты `sdk`, `sdk/db` и относительные `.js` внутри tgcloud |
| Endpoint contract | `export default async function(input, ctx)` |
| Проверенная авторизация | Только `ctx.initData.user.id`; платформа отклоняет неверный initData до выполнения |
| Вызов из React | Callback-контракт `Telegram.WebApp.Serverless.call` |
| Ошибки | `EndpointError` с машинным кодом; generic error для неожиданных исключений |
| SQLite | `table`, `integer`, `text`, `boolean`, `index`, `check`, `sql` из sdk/db |
| Асинхронные запросы | `await .all()`, `.get()`, `.run()`, `db.$count()` |
| RETURNING | Используется документированный массив строк для table-bound returning().run() |
| Изоляция | Owner predicate для SELECT/UPDATE/DELETE/count; INSERT устанавливает owner |
| Размещение frontend | `static.source: dist`, SPA, immutable только для хешированных assets |
| Совместимость Telegram Web | Нет X-Frame-Options или запрещающего frame-ancestors |
| Темы и смартфоны | themeChanged, safe area, адаптивный CSS, reduced motion, BackButton |
| Секреты | Только штатное состояние CLI, исключённое из Git; нет секрета в frontend |
| Миграции | После разрешения пользователя выполнен `tgcloud migrate --local --safe`: создана новая tasks без изменения существующих данных |
| Команды в чате | handlers/message; владелец из Telegram message.from.id, только личный чат |
| Inline-кнопки | handlers/callback_query; владелец из callback_query.from.id, никогда из callback_data |
| Меню | Официальные setMyCommands с chat scope и setChatMenuButton с MenuButtonWebApp |

Автоматические проверки логики запускаются с настоящей локальной SQLite и
тестовым адаптером документированного подмножества SDK. Они проверяют сохранность
после закрытия/открытия базы, CRUD, IDOR, подмену userId, изоляцию счётчиков,
идемпотентность, валидацию, SQL-параметры, фильтры и пагинацию.
Адаптер находится только в tests/ и не включается в deployment.

Расширение чат-бота сверено с официальной Bot API документацией:
https://core.telegram.org/bots/api. Проверено 12 backend-тестов: 6 исходных
и 6 для команд/кнопок. Чат-тесты покрывают все зарегистрированные команды,
регистрацию меню, общий CRUD с Mini App, повторную доставку /add, пагинацию,
поддельные task ID, несовпадение chat ID и отправителя, HTML-экранирование,
подтверждение и отмену удаления, устаревшие кнопки и сбой настройки меню.
Bot API вызовы в этих тестах перехватываются; реальные сообщения при разработке
не отправляются. После разрешения пользователя deploy и безопасная миграция
выполнены; чат использует опубликованные обработчики.

Официальный runtime дополнительно проверен командой `tgcloud run` для getProfile
с тестовым контекстом. Модули и объявления схемы успешно загрузились, профиль
вернулся в документированном формате. Это не проверка подлинности initData:
CLI run намеренно принимает непроверенный контекст разработчика.

Браузерные проверки используют официальный WebApp SDK, локальную SQLite и
тестовый перехват транспорта. Они покрывают мобильный CRUD, светлую/тёмную тему,
повторное открытие, ошибку refresh после успешной мутации, отмену удаления,
отсутствие горизонтального скролла и экран вне Telegram на нескольких ширинах.

С разрешения пользователя проект опубликован: cloud revision 1, 11 серверных
модулей и 4 статических файла. Webhook https://cloud.telegram.org/app8347651382/webhook
подписан на message и callback_query; pending updates = 0. CLI migrate --dry-run
подтвердил согласованность базы и опубликованной схемы. Публичный сайт вернул HTTP 200.
POST getProfile без initData и POST listTasks с поддельным initData оба вернули
HTTP 401 с error_type UNAUTHORIZED; неподписанный запрос не запускает endpoint.
Сценарий с подписанным initData и пользовательскими задачами дополнительно нужно
проверить из реального Telegram-аккаунта. Неподдерживаемые API, сервер npm, Express, Prisma,
Node.js API в tgcloud и локальное хранилище в production не используются.

Обновление дизайна опубликовано 10 октября 2026: cloud revision 2,
9 статических файлов, `tgcloud push dist/`. Интерфейс использует монохромную
палитру, локально размещённый Geist с кириллицей, карточки 24 px и элементы
управления 18 px. Тёмная тема следует colorScheme Telegram; цвета шапки,
фона и нижней панели установлены документированными методами с проверкой версии SDK.
`npm run build` и все 3 браузерных теста прошли. Проверены CRUD, повторное
открытие, ошибки, формы и отсутствие горизонтального скролла на 320/768/1440 px.
Все 9 опубликованных файлов вернули HTTP 200 и совпали с локальной сборкой
по SHA-256. CLI подтвердил синхронизацию static и webhook. Серверные модули
и схема этим обновлением не изменялись; миграции не запускались.

Расширение дедлайнов и напоминаний подготовлено локально 10 октября 2026.
Повторно проверены https://core.telegram.org/bots/serverless и npm-версия CLI:
0.2.0. В опубликованных документах нет durable timers, cron или scheduled jobs.
Поэтому автоматический запуск не заменяется таймером браузера: подготовлен
GitHub Actions workflow, вызывающий документированный CLI `run --ctx`.
Планировщик ещё не подключён; `remindersEnabled=false` проверяется сервером,
а интерфейс показывает недоступность автоматической отправки.

Добавлены `setTaskSchedule`, `getReminderCapabilities` и защищённый служебный
`processReminders`. Обычный клиент не может установить корневой maintenanceJob
в ctx: контекст задаёт платформа, а CLI run отдельно допускает контекст разработчика.
Передача такого поля через input или initData не разрешает обработку чужих задач.
Worker использует только sdk/api и sdk/db; Node-программа запуска CLI находится
в scripts/ и не включается в Telegram runtime. Пользовательские названия экранируются.

Пройдены 20 backend-тестов, включая новые сценарии миграции существующих данных,
UTC/offset, дедлайнов, IDOR, параллельного запуска, отмены, изменения сроков,
повторной доставки, 429 и блокировки бота. Все 4 браузерных теста прошли:
дедлайн при создании и изменении, удаление срока, просрочка, сохранение после
перезагрузки, отсутствие переполнения формы на 320 px, обе темы и разрешение
на сообщения через официальный requestWriteAccess. Проверена production-сборка.

CLI `migrate --local --dry-run` подтвердил 8 безопасных изменений (7 полей и
индекс), ничего не применял. Локальная SQLite-проверка подтвердила сохранность
существующих столбцов и нейтральные значения новых полей. CLI run загрузил
новые модули в настоящем Telegram runtime; getReminderCapabilities и служебный
processReminders вернули enabled:false. Настоящие напоминания не отправлялись.
На момент первоначальной проверки публикация расширения и миграция ещё не
были выполнены.

11 октября 2026 пользователь разрешил публикацию и подключение GitHub Actions
в аккаунте marsen5689. Повторные `npm run check` (20 backend-тестов и build)
и 4 браузерных сценария прошли. Сначала применён `migrate --local --safe`:
8 безопасных дополнений, 0 пропущенных изменений. Затем опубликованы модули
и frontend: cloud revision 3, 9 статических файлов. `remindersEnabled=false`
сохранён до подключения и проверки планировщика.

Подключение marsen5689 подтвердило права contents/workflows/actions write,
но создание репозитория отклонено `Resource not accessible by integration`,
а запрос публичного ключа Actions Secrets вернул 403. Репозиторий не создан,
CLI Access token никуда не передавался, workflow не запускался. Пользователю
переданы два необходимых шага в браузере: создать приватный SyToDoBot и
добавить секрет TGCLOUD_TOKEN. Это ограничение фактических прав подключения,
не дополнительное требование разрешить уже согласованную публикацию.

После публикации CLI подтвердил чистое состояние, синхронизацию webhook и
базы. Все 9 статических файлов вернули HTTP 200 и совпали с dist по SHA-256.
getProfile, setTaskSchedule и processReminders без initData вернули HTTP 401.
Реальный runtime getReminderCapabilities вернул enabled:false и precisionMinutes:5.
Доставка напоминаний в реальный чат в этом обновлении не проверена: scheduler
ещё не подключён.
